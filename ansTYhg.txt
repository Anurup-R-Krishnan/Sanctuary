### 2. Actual app split

Do you currently have:
apps/web
apps/desktop
apps/mobile

and are web + desktop both functional, or is one currently incomplete?
Also: is mobile still a real target, or should we temporarily remove/ignore it during the rewrite?

--- ANSWER ---
1. App split status:
   - apps/web: Active, primary React 19 + Vite 6 SPA. Contains the entire reader, library grid, statistics view, settings, and auth flow.
   - apps/desktop: Active Tauri v2 desktop application. However, it does NOT have its own separate React UI codebase. Its tauri.conf.json sets `frontendDist: "../../web/dist"` and `beforeBuildCommand: "VITE_DISABLE_AUTH=true npm --prefix ../web run build"`. In other words, Desktop is a native WebKit/WebView host wrapping the built `apps/web` bundle.
   - apps/mobile: Expo / React Native project (`@sanctuary/mobile`) with dedicated mobile screens, navigation, and a WebView reader.

2. Web + Desktop functionality:
   - Both Web and Desktop are functional.
   - `apps/web` compiles and runs cleanly via `bun run web:build` and `bun run dev`.
   - `apps/desktop` compiles and packages cleanly into an AppImage (`apps/desktop/build-appimage.sh`), running the web bundle in offline/guest mode (`VITE_DISABLE_AUTH=true`).

3. Mobile recommendation during rewrite:
   - Temporarily ignore/freeze mobile during the rewrite.
   - Web IS the desktop application interface. Keeping web and desktop unified is natural and fast.
   - Attempting to rewrite mobile simultaneously with a new reader engine will double the surface area and slow down iteration. Once the Foliate-js engine and shared data contracts (in `packages/core`) stabilize on desktop/web, mobile can be updated against those shared interfaces without friction.

--- DETAILED ARCHITECTURAL BREAKDOWN ---

* Where is the EPUB engine initialized?
  - Initialized in `apps/web/src/hooks/useReaderEngine.ts` inside a `useEffect` watching `[activeBookId, activeBlob, containerRef]`.
  - It constructs `new ReaderSession(...)` defined in `apps/web/src/reader/engine/ReaderSession.ts`.
  - Inside `ReaderSession.init()`, the book file ArrayBuffer is retrieved (with an in-memory cache `epubBufferCache` to avoid re-reading the Blob across layout changes) and passed to `openEpub(arrayBuffer, { replacements: "none" })` in `apps/web/src/utils/epub.ts`.
  - `openEpub()` invokes `ePub(source, options)` directly from the `epubjs` package.

* Where is the iframe/rendition created?
  - In `apps/web/src/reader/engine/ReaderSession.ts` within `buildRendition(readingDirection)`.
  - It executes:
    `this.rendition = this.epubBook.renderTo(this.container, {
        width: "100%",
        height: "100%",
        spread: flow?.continuous ? "none" : (flow?.spread ? "auto" : "none"),
        minSpreadWidth: flow?.spread ? 800 : Infinity,
        flow: flow?.continuous ? "scrolled" : "paginated",
        manager: flow?.continuous ? "continuous" : "default",
        allowScriptedContent: true,
        direction: readingDirection,
    });`
  - An `<iframe>` is dynamically generated by epub.js and appended to `this.container`.
  - To prevent epub.js sandbox errors and white flashes between chapter loads, a `MutationObserver` (`setupSandboxObserver`) removes the iframe's `sandbox` attribute and applies `preColorIframe` to set the iframe and inner document background colors before content renders.

* Where are pagination and locations handled?
  - Location generation: In `ReaderSession.ts`. First checks IndexedDB for pre-generated locations via `loadCachedLocations(this.bookId, fingerprint, 1024)` (`apps/web/src/reader/persistence/locationCache.ts`). If not cached, `generateLocationsInBackground()` executes `this.epubBook.locations.generate(1024)` inside a `requestIdleCallback` (or `setTimeout(..., 0)`) off the main thread.
  - Relocation: Handled in `ReaderSession.attachRenditionListeners()` via `this.rendition.on("relocated", this.handleRelocated)`. Inside `handleRelocated`, it captures `loc.start?.cfi`, calculates `progressFraction = epubBook.locations.percentageFromCfi(cfi)`, determines `locationIndex = epubBook.locations.locationFromCfi(cfi)`, maps chapter labels via `findTocLabel(href)`, and triggers `callbacks.onPositionChange()` debounced at 250ms.
  - Pagination (Next / Previous): In `ReaderSession.next()` and `ReaderSession.prev()`. Calls `rendition.next()` / `rendition.prev()` in paginated mode, or scrolls the container by 80% viewport height in continuous scroll mode.

* Where are CFI/bookmarks/highlights handled?
  - CFI: Extracted during `handleRelocated` from `loc.start?.cfi`. Forwarded through `useReaderEngine.ts` to `ReaderView.tsx` and saved via `onUpdateProgress(activeBookId, next.bookProgress, next.cfi)`.
  - Bookmarks: Stored directly on the `Book` model (`book.bookmarks: Bookmark[]`). Created/removed via `useReadingSession.ts` (`addBookmark`, `removeBookmark`), which calls `libraryService.addBookmark`/`removeBookmark`. Each bookmark stores `{ id: `${bookId}:${encodeURIComponent(bookmark.cfi)}`, cfi, label, progress, createdAt }`.
  - Highlights / Annotations: Managed by `apps/web/src/hooks/useReaderAnnotations.ts`. Selection is captured in `ReaderSession.ts` via `rendition.on("selected", (cfiRange, contents) => ...)`. Annotations are stored locally in IndexedDB via `apps/web/src/reader/persistence/annotationRepository.ts`. In `useReaderAnnotations.ts`, `renderAnnotation()` invokes `rendition.annotations.highlight(annotation.cfiRange, ...)` or `rendition.annotations.underline(...)` and repaints on `relocated`.

* Where is search implemented?
  - In `apps/web/src/hooks/useReaderSearch.ts` and `apps/web/src/components/reader/ReaderSearchPanel.tsx`.
  - `performSearch()` loops across each spine section using `epubBook.spine.each(async (section) => { await section.load(epubBook.load); const matches = section.find(trimmed); section.unload(); })`, mapping matches to `{ id, cfi, excerpt, href, chapterLabel }`. Clicking a result invokes `session.display(result.cfi)`.

* Where is TOC/navigation implemented?
  - Extracted in `ReaderSession.ts` via `this.epubBook.loaded.navigation.then(nav => { this.tocItems = nav.toc; this.callbacks.onTocReady(nav.toc); })`.
  - Rendered in `apps/web/src/components/reader/ReaderControls.tsx` (the TOC drawer) and `ReaderOverlay.tsx`.
  - Clicking a chapter invokes `engineRef.current.display(item.href)`.
  - `ReaderSession.findTocLabel(href)` scans the TOC tree to find the matching chapter title for display in the header and footer capsules.

--- STORES BREAKDOWN & SEPARATION AUDIT ---

Sanctuary has 6 dedicated Zustand stores located in `apps/web/src/store/`:

1. `useBookStore` (apps/web/src/store/useBookStore.ts):
   - Scope: Library books collection, sort/filter options, and derived state.
   - State: `books: Book[]`, `sortedBooks`, `recentBooks`, `favoriteBooks`, `seriesGroups`, `isLoading`, `sortBy`, `filterBy`.
   - Actions: `setBooks`, `setIsLoading`, `setSortBy`, `setFilterBy`, `updateDerivedState`, `getBookById`.

2. `useReaderProgressStore` (apps/web/src/store/useReaderProgressStore.ts):
   - Scope: Active reading session progress.
   - State: `active: { bookId: string, location: string, progress: number } | null`.
   - Actions: `setActiveBook`, `updateActiveProgress`, `clearActiveBook`.

3. `useSessionStore` (apps/web/src/store/useSessionStore.ts):
   - Scope: Authentication and user session mode.
   - State: `mode: 'initializing' | 'guest' | 'authenticated'`, `userId: string | null`.
   - Actions: `setSession`, `reset`.

4. `useSettingsStore` (apps/web/src/store/useSettingsStore.ts):
   - Scope: Complete reader preferences, typography, color themes, display toggles, speech, and keybinds.
   - State: `fontSize`, `lineHeight`, `textAlignment`, `fontPairing`, `maxTextWidth`, `hyphenation`, `pageMargin`, `paragraphSpacing`, `readerBackground`, `readerForeground`, `readerAccent`, `brightness`, `grayscale`, `showScrollbar`, `showPageCounter`, `showFloatingCapsule`, `progressBarType`, `barPosition`, `continuous`, `spread`, `direction`, `ttsVoiceURI`, `ttsRate`, `ttsPitch`, `keybinds`.

5. `useStatsStore` (apps/web/src/store/useStatsStore.ts):
   - Scope: Analytics, streaks, reading history, and goals.
   - State: `stats: ReadingStats` (currentStreak, longestStreak, totalBooksRead, totalReadingTime, averageReadingSpeed, hourly breakdown, authorNetwork), `goals: ReadingGoals | null`, `goalsStale`, `sessions: ReadingSession[]`.
   - Actions: `setStats`, `setGoals`, `setSessions`, `addSession`.

6. `useUIStore` (apps/web/src/store/useUIStore.ts):
   - Scope: Global UI navigation and app theme.
   - State: `view: View.LIBRARY | View.READER | View.STATS | View.SETTINGS`, `theme: Theme.LIGHT | Theme.DARK`, `searchTerm: string`.
   - Actions: `setView`, `toggleTheme`, `setSearchTerm`.

Store Separation Assessment:
- Separate: Settings (`useSettingsStore`), UI routing (`useUIStore`), Session/Auth (`useSessionStore`), and Stats (`useStatsStore`) are cleanly decoupled into independent stores.
- Mixed / Non-store areas:
  * Bookmarks: Mixed directly into `Book.bookmarks` inside `useBookStore`.
  * Reader engine / Rendition state: NOT in Zustand. ReaderSession is an imperative OOP class referenced via `useRef` in `ReaderView.tsx` and `useReaderEngine.ts`.
  * Annotations: Completely separated from Zustand. Kept in React hook state (`useReaderAnnotations.ts`) backed directly by an IndexedDB repository (`annotationRepository.ts`).
  * Reading progress: Partially duplicated — tracked transiently in `useReaderProgressStore` during active reading, but also debounced and saved into `Book.progress` and `Book.lastLocation` in `useBookStore`.

--- STORAGE MATRIX: WHAT IS STORED AND WHERE ---

1. Books (binary EPUB files):
   - Local: IndexedDB database `SanctuaryReaderDB`, object store `book_contents` (`{ bookId, content: Blob, mimeType, updatedAt }`). Managed by `apps/web/src/utils/db.ts` and `apps/web/src/services/bookContentRepository.ts`.
   - Cloud (when signed in): Cloudflare R2 bucket (`SANCTUARY_BUCKET`) via `/api/content/:id` (with fallback storage in Cloudflare D1 `books.content_blob`).

2. Metadata (title, author, totalPages, isFavorite, etc.):
   - Local: IndexedDB database `SanctuaryReaderDB`, object store `books`.
   - Cloud: Cloudflare D1 (SQLite) table `books` (columns `id`, `user_id`, `title`, `author`, `cover_url`, `progress`, `total_pages`, `last_location`, `bookmarks_json`, `is_favorite`, `updated_at`).

3. Reading Position & Progress:
   - Local: `book.progress` (percentage integer) and `book.lastLocation` (CFI string) in IndexedDB `books` object store.
   - Cloud: Cloudflare D1 table `books` columns `progress`, `last_location`, `updated_at`.

4. Bookmarks:
   - Local: Embedded inside the `bookmarks` array on each `Book` record in IndexedDB `books` store.
   - Cloud: Stored in Cloudflare D1 table `books` column `bookmarks_json` (serialized JSON array).

5. Highlights & Notes (Annotations):
   - Local: IndexedDB database `SanctuaryReaderDB`, object store `annotations` (`{ id, bookId, cfiRange, text, color, note, type, createdAt }`).
   - Cloud: NOT currently synced to cloud (local IndexedDB only).

6. Settings:
   - Local: `localStorage` under key `sanctuary-settings` (managed via `apps/web/src/components/ui/SettingsProvider.tsx`).
   - Cloud (when signed in): Cloudflare D1 table `user_settings` (columns `user_id`, `daily_goal`, `weekly_goal`, `theme_preset`, `font_scale`, `line_height`, `text_width`, etc.).

7. Thumbnails / Covers:
   - Local: Extracted from EPUB archive on import (`extractCoverBlobFromEpubSource` in `apps/web/src/utils/epub.ts`), converted to object URL or stored as data URI in `book.coverUrl` in IndexedDB `books` store.
   - Cloud: Stored in Cloudflare D1 table `books` column `cover_url`.

8. Additional persistent stores:
   - IndexedDB store `sessions`: Reading session history for statistics calculations (migrated from legacy localStorage).
   - IndexedDB store `reader_cache`: Cached locations generated by epub.js (`{ id: `${bookId}:${fingerprint}:${breakSize}`, locations }`).
   - IndexedDB store `mutations`: Offline sync queue mutations for synchronizing with Cloudflare Pages API when online.

--- TAURI ARCHITECTURAL AUDIT ---

Is Tauri currently just React → WebView or does Rust handle backend tasks?

Tauri is currently strictly `React → WebView`.

Evidence and Architecture:
1. `apps/desktop/src-tauri/src/main.rs`:
   - Contains only 30 lines of Rust.
   - Sets up a standard Tauri window and a basic "File" menu with an "Add EPUB…" menu item.
   - When "Add EPUB…" is clicked, it calls:
     `window.eval("window.dispatchEvent(new Event('sanctuary:add-book'))")`
     which simply dispatches a custom DOM event into the React frontend to open the HTML `<input type="file">`.
2. `apps/desktop/src-tauri/Cargo.toml`:
   - Dependencies: only `tauri = "2.0.0"`, `serde`, and `serde_json`.
   - Zero plugins: no `tauri-plugin-fs`, no `tauri-plugin-dialog`, no `tauri-plugin-sql`, no `tauri-plugin-upload`.
3. What Rust currently handles:
   - Filesystem: NO.
   - File importing: NO (browser file input reads files into ArrayBuffer/Blob).
   - Database: NO (frontend uses IndexedDB in the WebView).
   - Native dialogs: NO (frontend uses web input elements).
   - Background tasks: NO.
   - Book processing: NO (frontend parses EPUBs in JS).

Conclusion:
Sanctuary Desktop is currently a thin WebKit/Blink WebView wrapper around the production Vite build of `apps/web`.

--- AUTHENTICATION & BACKEND STATUS ---

Does Sanctuary currently have Clerk, local-only mode, sync/backend, accounts, cloud library?

Yes, Sanctuary currently has a dual-mode setup:

1. Local-Only / Guest Mode:
   - Enabled when `VITE_DISABLE_AUTH=true` or when the user clicks "Continue as Guest" on `AuthScreen`.
   - For desktop builds (`build-appimage.sh` and `tauri.conf.json`), `VITE_DISABLE_AUTH=true` is hardcoded at build time.
   - In guest mode, `GuestAuthProvider` supplies a mock auth context (`isSignedIn: false`, `user: null`), completely bypassing Clerk.
   - All books, reading sessions, progress, bookmarks, and settings work 100% locally and offline in IndexedDB and localStorage.

2. Clerk Authentication & Cloud Library:
   - When `VITE_DISABLE_AUTH !== "true"`, Clerk React (`@clerk/clerk-react`) handles user authentication (sign-up, sign-in, user sessions).
   - An authenticated session communicates with Cloudflare Pages Functions backend (`functions/api/`):
     * D1 (SQLite) stores user settings, books metadata, reading sessions, and goals.
     * R2 stores book binary contents.
   - `SyncQueue.ts` manages offline mutations and replays them when the connection is restored.
   - `MigrationDialog.tsx` prompts users when switching from guest to authenticated mode to migrate local books to their cloud account.

Should authentication remain in the rewrite?
- Yes, as an optional cloud sync layer, BUT the core reader architecture must be local-first and strictly decoupled from authentication.
- The reader engine, book content repository, annotation system, and bookmarking should operate directly against a local-first interface.
- Authentication and remote sync should sit in a separate synchronization adapter layer so the reader remains fast, reliable, and completely functional offline.

Audit of current EPUB reader functionality:

[✓] EPUB opens

[✓] Search (full-text search across spine sections with excerpts and jump-to-CFI)
[✓] Bookmarks (add/remove bookmarks with CFI location, label, and progress)
[✓] Highlights (text selection popup with color options)
[✓] Annotations (notes attached to highlights)
[✓] Progress (percentage, page counters, top/bottom progress bar)
[✓] Resume last position (restores saved CFI on open with fallback to chapter start)
[✓] Keyboard shortcuts (configurable keybindings for page turns, bookmarking, fullscreen, toggle UI, close)
[✓] Fullscreen (standard browser / window fullscreen toggle)
[✓] Text-to-speech / Read aloud (Web Speech API integration with voice/rate/pitch controls)
[✗] Layout switching (previously caused crashes and loops; mitigated with debounce and rendition rebuilding, but still constrained by epub.js)
[✗] Non-EPUB formats (unsupported; completely missing)

What is currently GOOD:
1. UI Polish & Aesthetics: The visual styling, typography controls, slide-out drawer, bottom bar, and color presets are very well designed and feel like a modern, premium reader.
2. Offline-first foundation: Guest mode works completely offline with IndexedDB storing both metadata and book files.
3. Resilience against corrupt positions: `displayWithFallbacks` prevents stale CFIs from bricking books on open.
4. Fast mode switching optimization: `setFlow()` reuses the parsed EPUB buffer and spine instead of reloading the entire ZIP archive from scratch.

What is currently BAD:
1. epub.js iframe coupling: epub.js creates an isolated iframe per rendition. This leads to white flashes between chapter loads (requiring MutationObserver style injections to mask), broken keyboard event bubbling (requiring manual event forwarding), and sandbox restrictions.
2. Location generation lag: `locations.generate(1024)` parses the entire book on the main thread, causing significant CPU and memory spikes on large EPUBs.
3. Fragile continuous scroll: epub.js scrolled flow is notoriously clunky, frequently desyncing or miscalculating scroll positions.
4. Annotation fragility: Annotations rendered via epub.js highlight API frequently detach or fail to repaint across page reflows or window resizes.
5. In-memory bloat: epub.js retains extensive internal object graphs, leading to memory accumulation during long reading sessions.

What is currently MISSING:
1. Multi-format support: No support whatsoever for FB2, MOBI, AZW, AZW3, TXT, HTML, or Markdown.
2. Native DOM pagination: Modern readers (like Foliate-js) paginate directly in the DOM or via clean shadow DOM / virtualized columns without the iframe baggage.
3. Fast spine/character-weight progress calculation without blocking the main thread with location generation.
4. Cloud sync for annotations (highlights and notes are currently trapped in local IndexedDB).
5. Native desktop performance optimizations (no native file streaming or Rust file importing).

  * Paginated and continuous scrolling modes
  * Full typography and theme adjustments (font size, font family, margins, line height, colors)

  * Bookmarking and annotations

### 10. What exactly do you mean by "rewrite"

Answer: Option B — Rebuild (preserving product behavior and UI, while rebuilding the internal architecture and reader engine).

Breakdown of what this means:
- PRESERVE:
  * Sanctuary's visual design system, UI layout, and styling (Library grid, Book cards, Reader drawers/menus, Stats dashboard, Settings controls, color presets).

  * Reader Engine: Drop `epubjs` completely. Adopt `foliate-js` decoders and renderer.

  * Progress Tracking: Replace `locations.generate(1024)` with lightweight spine/character-weight progress estimation.
  * State & Persistence: Cleanly separate local storage, reader engine state, and cloud sync into modular adapters.
