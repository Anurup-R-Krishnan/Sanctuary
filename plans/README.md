## Dependency & Ordering Rationale

1. **Plan 004 lands first**: Establishing the zero-warning baseline (`bun run lint` produces 0 warnings) and strengthening multi-format edge cases ensures all subsequent features build on an unblemished quality foundation.
2. **Plan 001 (TTS) and Plan 003 (D1 Sync) are independent**: They touch separate systems (`apps/web/src/reader/foliate` vs `functions/api/` & `packages/core`). Plan 001 adds continuous speech; Plan 003 ensures cross-device state and highlights persist.
3. **Plan 002 (OPDS)** builds on the stable multi-format pipeline and library service, enabling users to fetch books directly from Standard Ebooks and Gutenberg.

## Findings Considered and Rejected

- **Full CRDT (Yjs / Automerge) for Annotations**: Rejected as premature over-engineering. Single-user multi-device synchronization with monotonic progress resolution and timestamp-based D1 UPSERTs (`ON CONFLICT(id) DO UPDATE`) satisfies all requirements with near-zero bundle overhead (< 5 kB vs 50+ kB for Yjs).
- **External XML Parser (fast-xml-parser / xmldom)**: Rejected to protect the production web bundle budget (< 500 kB). The browser's native `DOMParser` parses OPDS 1.2 Atom feeds with zero added bytes.
- **Legacy epubjs Backward Compatibility Shims**: Rejected. Foliate completely replaces `epubjs` with 8 formats; retaining obsolete shims adds dead code and cognitive overhead.
